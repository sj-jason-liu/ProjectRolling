# 路人與車流系統規格

日期：2026-11-10。狀態：已確認（2026-11-10）；本次定稿不代表實作完成。

依據：GDD v0.2、[第一切片設計](GameLoop.md)、現有 SpawnManager／Somebody／CarMoves。Unity 6、3D 與 GDD 的清場、交管、入鏡 NG 為既定方向；**CT1–CT6 全部採用原建議預設，已確認（2026-11-10）；本文規則、數值、資料設計與範圍共同作為實作依據。GameLoop A1–A21 同日確認；A10／CT2 配置差異見 GameLoop §7.1。**

## 1. 設計目標

- 路人提供巡查與主動疏散壓力；車流提供預先封路與持續交管壓力。兩者於準備期開始活動，拍攝時入鏡造成 NG，讓玩家取捨清雜物、請離開與維持交管。
- 「雙向」指場景允許的不同方向都有交通來源，不要求同一個個體到終點立刻折返。避免目前路人隨機配對起終點、車輛 A→B 後瞬移回 A 所造成的單向感。
- 場景先決定合法通行範圍、方向與容量，難度只在合法選項內調整頻率與組成；困難不能讓車逆向、路人任意穿牆或從取景框內生成。
- 威脅必須可看見、可提前處理。增加頻率與雙向壓力之前，先確保單人能到達交管位置、疏散出口與清場區。

## 2. 場景限制與方向

### 2.1 場景標記

| 元素 | 需要的定義與通行規則 |
|---|---|
| 人行道／步行區 | 區域邊界、路徑節點、可接出口；一般路人只在此區及明確連接的穿越路段行走。雙向步行以兩條相反的有向路徑表示。 |
| 斑馬線 | 連接兩側人行道的專用步行路徑，標記與車道的衝突區、兩側等待點；不是整條馬路都可步行。 |
| 車道 | 有序路徑、入口、出口、允許車種、速限、停車線與排隊空間；汽機車皆遵守方向，不走人行道。 |
| 雙向道路 | 兩條分離、反向的車道路徑，各有上游停車線及入口；不是把同一條中心線隨機反轉。道路太窄則只開單向，交替放行留後續。 |
| 出入口 | 類型、朝向、可用路徑、生成安全空間、離場位置；路人與車輛不得任意混配起終點。生成／回收點須在取景框及主要可見活動區外。 |
| 疏散路徑／點 | 每條路人路徑對應可達的框外安全點及出口；請離開後不得為了抄近路再穿越取景區或未允許的車道。 |
| 取景區／交管區 | 獨立遊戲判定範圍；每個交管控制群組明列可控制的車道與停車線，不能憑距離自動影響所有車道。 |

道路旁的範例：南北側人行道各提供東→西、西→東；道路配置東行與西行各一車道。若此關卡只允許東行車，關閉西行路徑即可，不必改難度資產。路人進框路徑、駐足點與粉絲目標也必須落在允許步行的範圍，不能用行為類型繞過場景限制。

### 2.2 選路、阻塞與公平性

1. 先以場景啟用狀態、對象類型與合法連接過濾路徑，再依方向權重及同方向路徑權重抽選；方向是路徑的入口→出口，不是世界座標的固定正負軸。
2. 難度權重以合法方向重新正規化；只有單向時為 100%。沒有合法路徑或所有權重皆為零時停用該來源並提示配置錯誤，不能產生逆向路徑作為替代。
3. 入口被占用、容量已滿或路線暫時封閉時延後該次生成，保留已選路徑，不偷偷改從另一端出現；清空後仍維持最小生成間隔，不能累積後瞬間補出整批。
4. 請離開改走指定安全路徑。自然離場不等於完成疏散任務；到安全點且整個判定體離框才完成，沿用已確認的 A12／A17。無安全路徑時應報錯、停止使用該來源，不以瞬移當作疏散成功。
5. 車輛在對應停車線前排隊，不穿透前車；已越線者繼續前行，不倒車回線。雙向測試用一個交管群組同時控制兩條車道，每條仍有獨立停車線，降低單人兩端奔跑的負擔（CT2 已確認，2026-11-10）。
6. 啟用斑馬線時，採簡化互斥：車輛已占用衝突區時路人等待；否則路人先行、車輛在上游等待。等待點須在取景框外，車輛不得停在斑馬線內；不做碰撞傷害玩法。第一版先用不相交路線驗證雙向，斑馬線實際通行延後。
7. 最快對象從首次可見預警點到取景框至少有 4 秒行進時間；每方向都需檢查，不能只看生成點距離。停車線至框至少一個最大車身長，並留足煞停空間。速度提升後若不合格，降低速度或調整入口，不能犧牲預警。
8. 結算停止生成與移動／重置流程；重新整局才清空對象與排程。NG 不回收場上交通，也不重新播放首次 Action 排程。設備停拍時交通繼續，入鏡照常 NG，依已確認的 A16 執行。

## 3. 難度設定與數值

以下是**自由流量測試模式**起始值，不作為第一切片固定任務量。間隔以全場每一類來源計算（不是每入口各生一份），均勻抽樣；第一次生成也等待一次間隔。單位公尺以場景尺度校正，不直接當作既有模型的設定值。

| 參數 | 簡單 | 普通 | 困難 | 設計理由 |
|---|---:|---:|---:|---|
| 路人生成間隔 | 8–12 秒 | 5–8 秒 | 3–5 秒 | 逐步縮短巡查空檔；比目前無上限的 2–7 秒更可控。 |
| 車輛生成間隔（汽機車合計） | 12–18 秒 | 8–12 秒 | 5–8 秒 | 交管負擔逐步增加，不以車種各自生成倍增流量。 |
| 場上路人上限 | 3 | 5 | 7 | 包含駐足、已疏散但尚未離場者。 |
| 場上車輛上限 | 2 | 4 | 6 | 包含排隊車輛；另受各入口可容納數量限制。 |
| 主／次方向比例（路人、車輛各自抽選） | 80／20 | 60／40 | 50／50 | 從主要注意一端，逐步要求注意兩端；僅適用雙向合法場景。 |
| 路人基礎速度 | 1.0–1.2 公尺／秒 | 1.1–1.4 公尺／秒 | 1.2–1.6 公尺／秒 | 保留追上與互動時間；粉絲依 A13 再乘 1.2，仍受預警限制。 |
| 汽機車行進速度 | 2.0–2.5 公尺／秒 | 2.5–3.0 公尺／秒 | 3.0–3.5 公尺／秒 | 片場風格化低速；兩種車同速規則，避免先引入超車。 |
| 汽車／機車比例 | 75／25 | 50／50 | 40／60 | 呈現台灣巷弄組成；首版同樣可攔停，比例主要是視覺變化，不宣稱必然更難。 |
| 高峰波次 | 關閉 | 關閉 | 每 30 秒持續 8 秒，間隔 ×0.75 | 後續加入可預期的短壓力，不提高上限或突然加速。 |

速度於生成時抽樣，場景速限與預警安全上限取較低值。高峰依全局經過時間計算，提前 3 秒提示，準備／拍攝／NG 不重設波次；只影響下一次抽樣的間隔，不額外插入一批生成。高峰先延後實作。

有效上限＝難度上限與場景容量的較小值。容量包含車身、間距及框外排隊空間；某方向排滿只擋該方向，仍受全場上限約束。路徑或速度設定無法滿足 4 秒預警時，場景檢核應指出問題。

### 3.1 與固定任務排程的分工

- **固定排程驗收模式（首片預設，CT3 已確認，2026-11-10）：** 依 A11／A14，維持其 6 位 NPC、4 次車流及時間錨點，車種維持各兩次、NPC 每類兩位、未完成疏散者上限三位；不套用上表的頻率、車種比例或高峰。每筆排程明定合法路徑，可分配兩端以測雙向。場上總量另受安全容量限制。
- **自由流量測試模式：** 使用上表持續生成，供調頻率、方向與容量，暫不輸出正式星級，也不沿用固定 13 項分母。難度切換先限開局前，避免局中重置與突發補生。
- 固定排程因容量而延後時保留任務 ID，依到期先後處理，同類至少隔 1 秒放出一筆；未生成者仍依 A17 列未完成。已自然離場的 NPC 不占場上容量，但未完成任務狀態仍保留；「場上未完成疏散者」只計仍在場者。
- 未來若正式切片改採隨機頻率，須另訂開局就固定的有限任務配額及生成時間窗，再一起重審 A11／A14／A17／A18；本次維持已確認的固定評分分母與任務量。

## 4. 給 Engineer 的資料與行為需求

以下是資料責任需求，不指定類別名稱或提供實作碼。

| 資料位置 | 必要資料 | 必要行為 |
|---|---|---|
| 難度 ScriptableObject | 路人／車輛間隔、場上上限、方向權重、速度範圍、車種權重、波次設定 | 可共用於不同場景；不持有場景物件參照，不覆寫道路合法方向。 |
| 場景路徑元件 | 路徑 ID、類型、方向群組、有序節點、入口／出口、允許類型、權重、速限、啟用狀態 | 用箭頭及顏色顯示動線；移動全程留在合法走廊內，不能只設終點讓導航跨越禁區抄捷徑。 |
| 場景區域／出入口元件 | 步行／車道區、禁止區、生成範圍、預警點、回收區、容量／安全間距 | 配置時檢查可達性、重疊與預警距離；無效來源不生成並提供原因。 |
| 交管與疏散配置 | 控制群組、對應停車線、隊列容量、站位／錐槽、NPC 安全點與撤離路徑；後續的衝突區 | 支援多方向明確綁定；舉牌／交通錐仍沿用已確認的 A10（配置差異見 GameLoop §7.1），不擅改按鍵或完成條件。 |
| 關卡生成設定 | 模式、難度參照、場景允許來源、固定排程的時間錨點／類型／路徑／唯一任務 ID、測試亂數種子 | 固定與自由模式互斥，不能同時開啟而重複生成；同種子及同操作條件可重現測試。 |
| 執行中狀態 | 待生成事件、各類在場數、方向隊列、對象路徑／移動狀態、任務 ID／完成狀態、已觸發 NG 狀態 | 生成、自然離場、疏散完成與任務完成分開記錄；NG 不倒帶、結算取消待生成、整局重玩重設。 |

來源不足、路徑斷裂、沒有合法車種、出口在框內等需有可辨識的場景檢核訊息。除錯顯示至少含目前模式、難度、各類在場數／上限、下一次生成及被延後原因，方便 PM 比對測試。

## 5. 第一版最小範圍與驗收

此範圍已確認（2026-11-10），與 GameLoop 已確認的三類任務及 3／6／4 固定任務量共同實作。

**第一版納入：** 一張測試場景；人行道雙向路徑、兩條反向且分離的車道、框外進出口；可關閉單一方向；路人／車輛各自頻率、上限、方向權重與速度；汽機車類型欄位；固定排程／自由流量兩模式；堵入口延後生成、基本排隊及離場回收。交管與疏散依已確認切片規則接入，NG 與結算接受流程系統控制。三個難度資料可建立，但平衡先以普通測試。

**延後：** 斑馬線衝突通行、複雜路口／號誌、窄巷交替放行、超車、迴轉、動態改道、車禍／傷害、波次、局中切換難度、隨機模式正式評星、多人同步與新 NPC 行為。資料可預留，首版不把尚未支援的斑馬線路徑啟用。

驗收條件：

1. 單向場景套用任何難度都不逆向；雙向測試明排每端至少一位路人與一台車，方向與車道一致，離場後不在畫面內瞬移。
2. 自由模式空場、入口暢通時，生成間隔落在選定區間；大量抽樣的方向比例接近權重，短局不要求精確比例。固定模式則驗證排程，不能用隨機頻率判失敗。
3. 入口堵住／上限已滿不重疊生成；解除後不瞬間補生。各車道排隊不穿透，單向封閉不會使車改走對向。
4. 最高速度及粉絲倍率下，兩端首次可見到入框皆至少 4 秒；交管停車線有足夠煞停空間，玩家有合法可達站位。
5. 疏散後不再穿框，自然離場不誤記完成；固定任務 ID 不因生成延遲或 NG 重複登記。
6. 流程接入後驗證：準備入鏡不 NG；拍攝入鏡會 NG；整理不重播排程；結算後沒有新生成／重置，整局再試可乾淨重開。

## 6. 已確認決策

使用者於 2026-11-10 決定 CT1–CT6 全部採用各題原建議預設。

1. **CT1：已確認（2026-11-10）—雙向進出。** 兩端獨立進出，個體到出口回收，不在可見區掉頭；方向由合法路徑決定。
2. **CT2：已確認（2026-11-10）—雙向交管。** 兩條分離車道各有停車線，一個控制群組同步攔兩向；場景可關閉一向。此決策擴充 A10 的單車道配置；兩份原文的配置差異保留並列於 GameLoop §7.1 回報 PM。
3. **CT3：已確認（2026-11-10）—固定與自由模式。** 保留固定排程驗收，另提供不評星的自由流量測試；原定六位 NPC／四次車流與 GameLoop A11／A14 同日確認。
4. **CT4：已確認（2026-11-10）—難度數值與切換。** 採本文起始值，先普通、只在開局前選擇；優先調頻率／上限／方向，速度受 4 秒預警限制，高峰延後。
5. **CT5：已確認（2026-11-10）—首版不啟用穿越馬路。** 先做互不相交的人行道與車道；斑馬線資料與位置可規劃，通行留後續加入簡化互斥讓行。
6. **CT6：已確認（2026-11-10）—滿額或入口阻塞。** 延後且不瞬間補生；固定排程保留任務 ID／未完成狀態，自由模式最多保留每類一筆待生成事件，成功生成後才抽下一個間隔。

## 7. 與 GameLoop 已確認決策的關聯

| 決策 | 關聯與適用規則 |
|---|---|
| 1：時間與 Action | 固定模式沿用準備開始／首次 Action 兩種時間錨點；準備 45 秒自動 Action、有效拍攝 20 秒、全局 120 秒。 |
| 2：NG／重拍／玩家入鏡 | 交通持續且不倒帶；NG 至少整理 5 秒並待全員離框，無重拍次數上限，玩家入鏡也 NG，依 A8–A9。 |
| 3：原型輸入 | 依 A3／A10／A12／A15 的鍵盤操作接入舉牌、請離開與撿放；觸控留後續。 |
| 4：首片內容量 | CT2 擴充 A10 單車道的配置差異見 GameLoop §7.1；三類 NPC／汽機車／兩種交管與六位 NPC／四次車流皆已確認。CT3 自由頻率與固定排程互斥，不削減內容量。 |
| 5：設備停拍 | 依 A16 停拍 2 秒、保留 Take 進度；交通持續，停拍入鏡照常 NG。 |
| 6：評星 | 固定模式沿用 A17 的 13 項帳本及 A18 權重、門檻，耗時未完成仍給 1 星並標示未完成；自由模式不評星。未來若將自由模式納入正式評星，須另行確認有限配額與評分規則。 |
